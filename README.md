# Mac Informer

Mac Informer is a lightweight inventory and connectivity dashboard for managed
macOS computers. Each Mac periodically reports its current Wi-Fi and Ethernet
addresses to one internal server, making machines easy to find even when DHCP
leases change.

The project targets small IT environments where DNS records are not always
available or reliable. It uses standard macOS services, a small Python server,
SQLite, shell scripts, and HTTPS.

## Features

- Wi-Fi and Ethernet IP and MAC addresses
- Computer name, console user, and last-seen time
- Online and stale status based on recent heartbeats
- Automatic room grouping from hostnames such as `R2054M01`
- Screen Sharing links using `vnc://`
- Wake-on-LAN for individual Macs and rooms
- Ansible-compatible YAML inventory export
- Automatic startup on server and clients using LaunchDaemons
- HTTPS through Caddy with an internal certificate authority

## Architecture

```text
Managed Mac clients
  report.sh every 5 minutes
          |
          | HTTPS POST /api/heartbeat (TCP 443)
          v
Caddy reverse proxy on the server Mac
          |
          | HTTP on localhost only
          v
Python server.py -> SQLite database -> Web dashboard
```

The client initiates every heartbeat. No inbound connection to a client is
required for reporting. VNC, SSH deployment, and Wake-on-LAN are optional and
have separate network requirements.

## Requirements

### Server Mac

- macOS and Python 3
- [Caddy](https://caddyserver.com/) installed locally
- A static IP address or DHCP reservation
- TCP port 443 reachable from managed client networks

### Client Macs

- macOS and administrator access for installation
- Network access to the server on TCP port 443
- The public CA certificate generated by the server installer

## Security model

Mac Informer uses two separate credentials:

1. A long random bearer token authenticates client heartbeats.
2. A dashboard password protects inventory, exports, VNC links, and wake
   actions. The dashboard username is `admin`.

Caddy terminates HTTPS on port 443. Python listens only on `127.0.0.1`, so its
local HTTP connection is not exposed to the network. Server configuration is
stored with root-only permissions.

This repository excludes operational databases, tokens, passwords, host lists,
organization-specific certificates, and deployment payloads. Never commit a
completed configuration or any Caddy private key.

## Install the server

Generate a shared token:

```sh
openssl rand -hex 32
```

Install Caddy if necessary:

```sh
brew install caddy
```

Copy the command from
[examples/server-install.env.example](examples/server-install.env.example),
replace the placeholders locally, and run it from the project directory.

The installer:

- installs the application under `/Library/Application Support/MacInformer`;
- creates root-protected configuration;
- installs LaunchDaemons for Python and Caddy;
- starts both services immediately and after every reboot;
- creates a private HTTPS CA and a public client certificate.

Open `https://SERVER_IP` and sign in with username `admin`.

### Copy the public CA certificate

After installation, copy the server's public certificate into the client
folder:

```sh
sudo cp \
  "/Library/Application Support/MacInformer/mac-informer-root-ca.crt" \
  "/path/to/Mac Informer/client/mac-informer-root-ca.crt"
```

The `.crt` file is public and may be distributed to clients. Do not copy the
Caddy data directory because it also contains the private CA key.

## Install a client

Place `mac-informer-root-ca.crt` beside `client/install-client.sh`. Copy the
`client` folder to the target Mac, then use the command in
[examples/client-install.env.example](examples/client-install.env.example).

The installer places the reporter in a permanent root-owned directory and
starts a LaunchDaemon. It reports immediately, every five minutes, and after
the Mac wakes. Temporary network failures are retried three times.

Each heartbeat contains:

- stable hardware UUID
- computer name and current console username
- active Wi-Fi interface, IPv4 address, and MAC address
- active Ethernet interface, IPv4 address, and MAC address

## Dashboard behavior

A heartbeat received within ten minutes appears as **Online**. An older record
appears as **Stale**. Stale only means the server has not heard from that Mac
recently; the Mac may be asleep, disconnected, removed, or unable to reach the
server.

Hostnames are grouped by their first five characters. For example, `R2054M01`
belongs to room `2054`. Other naming schemes form their own groups.

Wake-on-LAN sends magic packets for every known Wi-Fi and Ethernet MAC address.
Success depends on Mac power settings and how the network handles broadcast
packets, particularly across VLANs.

## Network requirements

Required for reporting:

```text
Client networks -> server: TCP 443 (HTTPS)
```

Optional features:

```text
Administrator/server -> clients: TCP 5900 (Screen Sharing/VNC)
Deployment computer  -> clients: TCP 22   (SSH/SCP deployment)
Server               -> client VLANs: UDP 9 broadcast (Wake-on-LAN)
```

Firewall rules should be limited to the server and managed client networks,
not opened globally.

## Logs and troubleshooting

Client logs:

```sh
sudo tail -n 50 "/Library/Logs/MacInformer/reporter-error.log"
sudo tail -f "/Library/Logs/MacInformer/reporter.log"
```

Server logs:

```sh
sudo tail -n 50 "/Library/Logs/MacInformer/server-error.log"
sudo tail -n 50 "/Library/Logs/MacInformer/caddy-error.log"
```

A curl exit code `28` means the connection timed out. Check routing, VLAN ACLs,
firewall rules, the server address, and TCP 443 reachability before debugging
the reporter.

Health check from a client:

```sh
curl --cacert ./mac-informer-root-ca.crt https://SERVER_IP/health
```

A healthy server responds with `OK`.

## Uninstall a client

```sh
sudo ./Client-Uninstall/uninstall-client.sh
```

The server retains the previous record, which later becomes stale. This
preserves inventory history and avoids accidental server-side deletion.

## Before publishing

Inspect exactly what Git will include before every push:

```sh
git status --short
git ls-files
```

Only source code, public documentation, plist files, and placeholder examples
should appear. Databases and local deployment material must remain untracked.

## Current scope and possible next steps

This is an internal-network administration tool, not a public internet
service. Useful future improvements include per-device credentials, token
rotation, audit logging, pagination, automated tests, and a more polished
responsive dashboard.
